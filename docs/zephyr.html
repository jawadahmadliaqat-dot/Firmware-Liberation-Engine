Zephyr echo_bot PASS

Interrupt-driven UART echo sample from Zephyr v4.4.2, for the nRF52840 DK, built from public source. Ground truth

126/126 code-true, 0 unexplained extras. Recovered: SoC init errata 29, clock control 59, RTC system timer 32, SoC init 4, NVMC wait 1, GPPI channel-enable 1 (from the UARTE driver — the only recovered UART-layer touch, and it is a PPI register).

Structural miss, stated plainly and not softened. The ENTIRE UARTE driver layer is missing: 20+ functions (init, poll in/out, FIFO fill/read, all interrupt handlers, error check) at 0 findings, and the UARTE0 register bucket has zero findings. Pinctrl/pin-select writes are missing too. Mechanism, source-verified: the peripheral base lives in a read-only config struct, accessed through the device struct, but the device pointer arrives only through device-API indirect dispatch, which per-site binding (direct calls only) never resolves. Bare-metal nRF52 recovers 66 UARTE findings because its instance is bound through direct calls; the clock driver recovers here only because it uses compile-time-constant macros. Generic PASS means only that what was found stayed in-window — here the sample's main peripheral is absent from the result.

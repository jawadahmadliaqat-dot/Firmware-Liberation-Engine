Formal proof of what your firmware really touches.

Ghidra lifts firmware to P-Code. ExtractIR extracts MMIO, port, MSR, protocol and BAR facts. A Lean 4 verifier checks whether every recovered access stays inside its allowed window and peripheral family. This site shows only real reports, plus two labelled synthetic demos. It does not run firmware.

Engine v3.26 · 36-target regression 31 PASS / 5 FAIL, 0 mismatches · Corpus: 1,885 fixed findings across 6 stacks, plus 11 P5 real targets reported separately below.

How to read a card: fixed = accesses the engine is certain about; may = accesses that are possible but not certain; verdict = the Lean checker's answer on the recovered accesses. A PASS means only that what was found stayed inside its allowed window. It is not proof the extraction is complete.

Real firmware, real violations: none so far. The P5 hunt below (11 new real targets, Oct 30, 2026) ended in an honest zero: every FAIL it met was triaged as an allowlist gap, an empty-trace coverage limit, or a deliberate probe control — not a bug.

What the engine checks (v3.26, Lean generic mode)

  • In-window addresses — every fixed access inside the architecture's MMIO window.
  • Driver confinement (bmp mode) — each driver family touches only its own peripherals.
  • Port/MSR confinement — every port/MSR entry against an architectural allowlist. v3.22 closed the CpuDxe gap with four named MSRs, each identified from Intel documentation: 0x17 IA32_PLATFORM_ID (read), 0x79 IA32_BIOS_UPDT_TRIG (microcode trigger), 0x830 IA32_X2APIC_ICR (AP bring-up), 0x982 IA32_TME_ACTIVATE (memory-encryption status). Named entries only, no blanket range; the allowlist stays index-granular, not direction-granular. v3.23 closed two further allowlist gaps from the evaluation round with five named MSRs, each identified from Intel documentation: 0x3A IA32_FEATURE_CONTROL, 0x80F Spurious Interrupt Vector Register, 0x832 LVT Timer Register, 0x838 Initial Count Timer, 0x83E Divide Config Timer.
  • Clock-enable-before-use — every used STM32 peripheral's gate register touched.
  • Bounds — no computed-pointer copy/transfer with an unsound-only guard. Synthetic precision TP=17, FP=0, FN=0, TN=16 (33 cases). v3.25 closed the signed-masking gap: the first branch after a comparison, before the copy, must gate the copy — proven on the class-level control fc_signed_mask. v3.26 closed the caller-check masking gap: a recorded caller check must gate the call edge — proven on cm_caller_mask with the cm_caller_gate control (genuine gating still suppresses, so the fix is not over-broad). Caveats, stated plainly: 0 corpus-output changes on the current 46-target set for both fixes; only signed-masking is proven in both — the wide half is unproven (no report in corpus has ever exercised a wide-check guard; treat as untested, not fixed, on these ISAs).
  • Boundary — no must-proven access crossing a configured security boundary (violation, unknown-agent and unknown-region counts reported, never silent). Synthetic contract 16/16; Zephyr MPU trophy exactly 1 violation; SAU two-stage proof, both axes: the non-secure build FAILs with exactly 5 violations, the secure build FAILs with exactly 1.

Honest negative, stated on the same page: the engine does not flag eSPI CVE-2026-78119 (PASS/PASS — the parse path is invisible to the must lens). The guide never overclaims.

Honest limits (one line each)

  • Generic PASS means only "what was found stayed in-window" — not proof of security. Proven twice: CVE-2026-11743 (vulnerable firmware passed before the bounds property) and eSPI CVE-2026-78119 (still passes).
  • Stripped binaries: generic mode only — bmp mode passes vacuously on stripped input, never quote it.
  • Clock-enable v1: order-free, not must-precede; register granularity, not bit; no-RCC firmware vacuous PASS.
  • F4 USART2 invisible (Gap B, needs a redesign, not a patch); LPUART enable→disable→use not caught.
  • Boundary V1.5 scope: static profiles + learned tables + thread attribution; config-write learning design-only; a boundary violation is a necessary condition for privilege escalation, NOT proof of an exploit.
  • Non-live 21 (all-slots seeding) is DELIBERATELY NOT enabled — a finding must mean "does call", not "could call"; deferred until a labelled JSON shape exists.
  • 16-bit real mode now has a raw-binary import path plus a segmented adapter, proven on synthetic Real-Mode targets; far-target discovery, Protected Mode, and A20 policy remain open.
  • RV64/MIPS64 calls and jump tables resolve on fixtures only; real targets are unproven (no toolchain here).
  • Real violations found in shipped firmware: 0. The FAILs that exist are intentional synthetic demos and the genuinely-empty traces of Sata, Virtio and acpi-mcfg; the 124-target OVMF evaluation round's 73 FAILs are likewise empty-trace coverage FAILs, counted separately; the MPU/SAU boundary violations are on purpose-built proof targets.
